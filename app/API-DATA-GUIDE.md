# API and Browser Data Guide

This guide documents the frontend's live backend requests and the browser data used to build them. It reflects the current client code, not the backend's validation or persistence behavior.

## API Base URL

The API base URL is defined in [API.js](API.js) as `API_BASE_URL`:

```js
const API_BASE_URL = "http://localhost:8080";
```

The endpoint helper functions in that file build the request URLs. Logout currently uses the same base URL directly in `shared/store.js`. The frontend does not attach an authentication token or send the entire browser storage object with requests.

| `POST /verify`                                                    | JSON: `email`, `otp`                                                                                                                                        | `email` from session storage key `otp_email`; `otp` from the OTP form, trimmed.                                                                                                                                                                                                                                                                                                                                    |

## Browser Storage

| Storage and key                     | What the frontend keeps                                                                                                                                      | Sent to backend?                                                                                                                                                                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `localStorage.clarity_state_v1`     | Shared app state: `currentUser`, `users`, roadmaps/custom roadmap and tracker state, and settings. Login populates the current user from the login response. | Not sent as a whole. Specific values are extracted: current email/username for profile, logout, payments, roadmaps and trackers; custom tracker state is mapped into the `/Custom_Tracker` payload. Settings and unrelated state are not sent. |
| `localStorage.latestRoadmap`        | Answers from the roadmap creation flow.                                                                                                                      | Selected category, name, and level are used as encoded path values for the roadmap-template request.                                                                                                                                           |
| `localStorage.roadmapCache`         | Roadmap data received or assembled by dashboard/roadmap flows.                                                                                               | Selected roadmap details are mapped into the `/tracker` request's fields and `jsonData`; the storage object itself is not sent.                                                                                                                |
| `localStorage.selectedRoadmap`      | Key identifying the selected cached roadmap.                                                                                                                 | No; used locally to select an entry from `roadmapCache`.                                                                                                                                                                                       |
| `localStorage.selected_tracker`     | Selected tracker record and locally updated progress.                                                                                                        | Selected fields and serialized updated roadmap data are sent by `/save_tracker`; the complete storage value is not sent wholesale.                                                                                                             |
| `localStorage.progress_{trackerId}` | Per-tracker IDs for locally persisted progress.                                                                                                              | Not sent directly. Progress is applied to tracker data before `/save_tracker` is called.                                                                                                                                                       |
| `localStorage.clarity_user_plan`    | Cached plan text returned by `GET /plan/{email}`.                                                                                                            | Not sent.                                                                                                                                                                                                                                      |
| `localStorage.clarity_data`         | UI preference data used for theme selection in the individual tracker.                                                                                       | Not sent.                                                                                                                                                                                                                                      |
| `sessionStorage.otp_email`          | Email retained between sending an OTP and verifying/changing the password.                                                                                   | Yes, as the `email` field in `/verify` and `/editPassword`.                                                                                                                                                                                    |
| `sessionStorage.roadmapSource`      | Navigation source used to decide whether to show the Track action.                                                                                           | Not sent.                                                                                                                                                                                                                                      |

Logout clears local storage after backend success. Successful account deletion clears both local and session storage.

## Data-Handling Notes

- Form values are sent as JSON only on the endpoints listed above; static roadmap category/name/level/email values are path parameters, and tracker list email values are query parameters.
- Passwords are included in the login, registration, and password-edit JSON request bodies. The configured API URL uses plain HTTP on localhost; use HTTPS when connecting to a deployed backend.
- Backend responses are cached or rendered by the frontend in several flows. This guide lists frontend request inputs, not response schemas.
- `custom.js` currently does not `await` the `/Custom_Roadmap` fetch before checking `response.ok` and reading JSON. The request is initiated, but that caller's success/error handling treats the returned Promise as a Response and will not work correctly until the fetch is awaited.

## Request Call Sites

Endpoint calls are implemented in `login.js`, `register.js`, `profile.js`, `otp_verify.js`, `passwordEdit.js`, `dashboard.js`, `new-roadmap.js`, `roadmap.js`, `custom.js`, `custom-tracker.js`, `tracker.js`, `individuaaltracker.js`, `upgrade.js`, and `shared/store.js`.
